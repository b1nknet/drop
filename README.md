# drop.

비밀번호로 보호하는 작은 파일 보관함.

**drop.**은 서버의 폴더 하나를 웹에서 사용하는 셀프 호스팅 파일 보관함입니다.
공유 비밀번호로 로그인하고, 브라우저에서 파일을 올리고 내려받거나 삭제할 수 있습니다.
파일은 지정한 폴더에 그대로 저장하며, 별도 데이터베이스나 프런트엔드 빌드 과정 없이 실행합니다.

## 주요 기능

- **파일 업로드** — 드래그 앤 드롭과 여러 파일 선택, 순차 전송, 파일별 진행률과 취소 기능
- **파일 관리** — 이름 검색, 최근 수정일·이름·크기 정렬, 파일 수와 전체 크기 표시
- **다운로드와 삭제** — 로그인한 사용자만 접근하며, 삭제 전 확인 제공
- **중복 이름 처리** — `report.pdf`, `report (1).pdf`처럼 저장해 기존 파일 보존
- **화면 설정** — 모바일 대응 레이아웃, 라이트·다크 모드, 브라우저에 테마 선택 저장

모든 사용자는 같은 비밀번호와 파일 공간을 사용합니다. 개별 계정, 사용자별 권한,
공개 공유 링크, 폴더 탐색, 파일 미리보기, 휴지통은 제공하지 않습니다.

## Docker Compose로 시작하기

Docker와 Docker Compose가 설치된 환경에서 프로젝트 루트를 기준으로 실행합니다.

### 1. 환경 설정

처음 설정할 때 예제 파일을 복사하고 저장 폴더를 만듭니다.
이미 `.env`가 있다면 기존 파일을 수정하세요.

```sh
cp .env.example .env
mkdir -p ./data
```

`.env`의 `APP_PASSWORD=changeme`을 사용할 비밀번호로 바꿉니다.
12자 이상의 충분히 긴 비밀번호를 권장합니다. 현재 애플리케이션은 최소 길이를 강제하지 않습니다.
`$`나 `#` 등이 포함된 값은 작은따옴표로 감싸세요.

Linux에서는 다음 명령으로 저장 폴더를 사용할 사용자의 UID와 GID를 확인하고,
`.env`의 `APP_UID`, `APP_GID`를 맞춥니다.

```sh
id -u
id -g
```

다른 저장 폴더를 사용하려면 `UPLOAD_DIR`에 해당 경로를 지정하세요.
Compose는 이 폴더를 자동 생성하지 않으므로, 미리 만들고 컨테이너 실행 사용자가
파일을 읽고 쓰고 삭제할 수 있도록 권한을 설정해야 합니다.

### 2. 실행

```sh
docker compose up -d --build
```

기본 접속 주소는 [http://localhost:8080](http://localhost:8080)입니다.
서버에서 실행했다면 `localhost` 대신 서버 주소로 접속하고, 설정한 비밀번호로 로그인합니다.

Compose는 기본적으로 호스트의 `8080` 포트를 컨테이너의 `8000` 포트에 연결하고,
`./data`를 컨테이너의 `/data`에 마운트합니다. `PORT`로 호스트 포트를 바꿀 수 있습니다.

### 3. 상태 확인과 종료

```sh
docker compose ps
docker compose logs -f drive
docker compose down
```

상태 확인 경로는 `GET /health`이며, 정상 응답은 `{"status":"ok"}`입니다.
Compose에도 이 경로를 호출하는 healthcheck가 설정되어 있습니다.
컨테이너를 종료하거나 다시 만들어도 호스트 저장 폴더의 파일은 유지됩니다.

`.env`를 변경했다면 다음 명령으로 컨테이너에 반영합니다.

```sh
docker compose up -d --force-recreate
```

## 환경 변수

| 변수                  | 기본값 또는 예제 값                    | 설명                                                                                      |
| --------------------- | -------------------------------------- | ----------------------------------------------------------------------------------------- |
| `APP_PASSWORD`        | 예제: `changeme`                       | 모든 사용자가 공유하는 로그인 비밀번호. Compose에서는 필수이며 사용 전에 변경해야 합니다. |
| `UPLOAD_DIR`          | `./data`                               | Compose에서 마운트할 호스트 저장 폴더                                                     |
| `PORT`                | `8080`                                 | Compose에서 공개할 호스트 포트                                                            |
| `APP_UID` / `APP_GID` | `1000` / `1000`                        | Compose 컨테이너를 실행할 사용자·그룹 ID                                                  |
| `DATA_DIR`            | 직접 실행: `./data`, 컨테이너: `/data` | 애플리케이션이 파일을 저장할 경로                                                         |
| `MAX_UPLOAD_MB`       | `1024`                                 | 파일 하나의 업로드 제한. 단위는 MiB이며, 기본값은 1 GiB입니다.                            |
| `SESSION_HOURS`       | `12`                                   | 로그인 시점부터 계산하는 세션 유효 시간                                                   |
| `COOKIE_SECURE`       | `false`                                | `true`이면 세션 쿠키를 HTTPS 연결에서만 전송                                              |

`MAX_UPLOAD_MB`와 `SESSION_HOURS`는 양의 정수여야 합니다.
`UPLOAD_DIR`, `PORT`, `APP_UID`, `APP_GID`는 Compose 설정용이며,
Python 애플리케이션을 직접 실행할 때는 적용되지 않습니다.
Compose 내부 저장 경로는 `/data`로 고정되어 있으므로 호스트 경로는 `UPLOAD_DIR`로 변경합니다.

## 사용 방법과 저장 방식

1. 설정한 공유 비밀번호로 로그인합니다.
2. 화면에 파일을 끌어다 놓거나 **파일 선택**으로 여러 파일을 고릅니다.
3. 업로드 목록에서 진행률을 확인합니다. 여러 파일은 하나씩 전송되며, 대기 중이거나 전송 중인 항목을 취소할 수 있습니다.
4. 파일 목록에서 검색·정렬하고, 각 파일의 다운로드 또는 삭제 버튼을 사용합니다.

삭제는 호스트의 실제 파일을 즉시 제거합니다. 휴지통이나 복구 기능이 없으므로
보관할 파일은 별도로 백업하세요.

### 저장 폴더

```text
data/
├── report.pdf
├── report (1).pdf
├── 회의 자료.txt
└── .drop-tmp/        # 업로드 중인 임시 파일
```

- 저장 폴더 바로 아래의 일반 파일만 표시합니다. 기존 파일도 이름 규칙에 맞으면 목록에 나타납니다.
- 숨김 파일, 하위 폴더, 심볼릭 링크, 특수 파일은 목록과 파일 작업에서 제외합니다.
- 이름은 UTF-8 기준 최대 240바이트이며, 앞뒤 공백, `/`, `\`, 제어 문자 등을 허용하지 않습니다.
- 업로드는 `.drop-tmp`에 기록한 뒤 완료된 파일만 최종 이름으로 공개합니다. 실패하거나 연결이 끊기면 임시 파일을 정리하고, 재시작 시 남아 있는 업로드 임시 파일도 정리합니다.
- 파일 공개에 하드 링크를 사용하므로 저장 파일시스템이 하드 링크를 지원해야 합니다.
- 파일은 원래 내용 그대로 저장합니다. 애플리케이션에서 저장 파일을 암호화하지 않습니다.

목록의 날짜는 파일시스템의 수정 시각입니다. 외부에서 추가하거나 수정한 파일의 변경 사항은
목록 새로고침으로 확인할 수 있습니다. 전체 크기는 목록에 표시되는 파일의 합계이며,
디스크 여유 공간이나 저장소 전체 용량을 뜻하지 않습니다.

업로드를 취소하거나 연결이 끊어진 시점에 서버 저장이 이미 끝났을 수도 있습니다.
재시도하기 전에 목록을 새로고침해 저장 여부를 확인하세요.

## 운영 시 알아둘 점

### 세션과 실행 프로세스

세션과 로그인 시도 제한은 프로세스 메모리에 보관합니다. **단일 인스턴스, 단일 worker로 실행해야 합니다.**
여러 worker나 복제본을 사용하면 요청을 받은 프로세스에 따라 인증 상태가 달라질 수 있습니다.
기본 Docker 실행 명령은 `--workers 1`을 사용합니다.

재시작하면 저장 파일은 남고 모든 로그인 세션은 만료됩니다.
로그아웃한 세션의 쿠키를 다시 사용해도 접근할 수 없습니다.
비밀번호 변경도 환경 변수를 수정하고 프로세스 또는 컨테이너를 다시 시작해 반영합니다.

### 인증과 요청 보호

- 비밀번호 검증에는 `scrypt`를 사용합니다.
- 세션 쿠키는 `HttpOnly`, `SameSite=Strict`를 사용하며, HTTPS 전용 여부는 `COOKIE_SECURE`로 설정합니다.
- 업로드·삭제·로그아웃에는 세션에 연결된 CSRF 토큰이 필요하고, 변경 요청에 `Origin`이 있으면 서버의 `Host`와 일치하는지 확인합니다.
- 로그인 시도는 5분 동안 IP별 최대 5회, 전체 최대 100회로 제한합니다. 성공한 로그인도 시도 횟수에 포함합니다.
- 파일 다운로드는 첨부 파일로 전송하며, 경로 이동과 심볼릭 링크를 통한 접근을 차단합니다.

### HTTPS 리버스 프록시

HTTPS를 제공하는 리버스 프록시 뒤에서 운영할 때는 `COOKIE_SECURE=true`로 설정하고
컨테이너를 다시 만드세요. HTTP 접속에서는 이 쿠키가 전송되지 않아 로그인이 유지되지 않습니다.

프록시는 브라우저가 요청한 `Host`를 백엔드에 전달해야 합니다.
또한 프록시의 요청 본문 크기 제한과 전송 시간 제한이 업로드할 파일을 수용하도록 설정해야 합니다.

기본 실행 명령은 `--no-proxy-headers`를 사용합니다.
프록시 뒤에서는 애플리케이션이 보는 프록시 주소를 기준으로 IP별 로그인 제한이 적용되므로,
같은 프록시를 거치는 사용자가 제한을 공유할 수 있습니다.

## 로컬 실행과 개발

Python **3.14**, `uv`가 필요합니다. 운영 코드는 Linux 파일시스템 기능인
`O_NOFOLLOW` 등을 사용하므로 Linux 환경을 기준으로 실행하세요.
웹 개발 도구를 사용하려면 Node.js **24 이상**도 필요합니다.
프로젝트의 버전 파일은 Python 3.14와 Node.js 24를 지정합니다.

처음 실행한다면 앞의 환경 설정 절차에 따라 `.env`와 저장 폴더를 준비합니다.

```sh
uv sync --locked
uv run --locked --env-file .env uvicorn app.main:app --host 127.0.0.1 --port 8080 --workers 1 --no-proxy-headers --no-access-log
```

[http://localhost:8080](http://localhost:8080)에서 확인할 수 있습니다.
이 명령은 `.env`를 명시적으로 불러옵니다. 직접 실행 시 저장 폴더를 바꾸려면
`DATA_DIR`를 설정하고, 포트는 `--port` 인자로 지정하세요.

HTML, CSS, JavaScript는 `app/static/`에서 바로 제공합니다.
Node.js와 npm 패키지는 코드 검사와 포맷용이며, 앱 실행을 위한 빌드 단계는 없습니다.

### 검사 명령

```sh
npm ci
npm run check
```

`npm run check`는 Python·JavaScript 린트, 코드·설정·문서 포맷 검사, Python 테스트를 실행합니다.
필요한 항목만 따로 실행할 수도 있습니다.

| 명령                                  | 작업                            |
| ------------------------------------- | ------------------------------- |
| `npm run lint`                        | Ruff와 ESLint 검사              |
| `npm run format:check`                | Ruff와 Prettier 포맷 검사       |
| `npm run format`                      | Python·웹 파일과 문서 포맷 적용 |
| `npm run lint:fix`                    | 린트 자동 수정 후 포맷 적용     |
| `npm test`                            | pytest 실행                     |
| `uv run --locked python -m pytest -q` | npm 없이 Python 테스트 실행     |

테스트는 임시 저장 폴더를 사용하며 인증, CSRF, 업로드·다운로드·삭제, 중복 이름과 동시 업로드,
파일명 검증, 용량 초과와 디스크 오류, 세션 만료와 재시작 동작을 확인합니다.
CI는 `main`·`develop` 브랜치에 push하거나 두 브랜치를 대상으로 PR을 생성·갱신할 때,
또는 수동 실행 시 Python 검사와 웹 검사를 수행합니다.

## API

자동 API 문서와 OpenAPI 경로는 비활성화되어 있습니다.

| 메서드   | 경로                | 인증             | 동작                                                |
| -------- | ------------------- | ---------------- | --------------------------------------------------- |
| `GET`    | `/health`           | 불필요           | 상태 확인                                           |
| `POST`   | `/api/login`        | 불필요           | JSON `{"password":"…"}`로 로그인하고 세션 쿠키 발급 |
| `GET`    | `/api/session`      | 세션 쿠키        | `csrf_token`, `max_upload_bytes` 조회               |
| `POST`   | `/api/logout`       | 세션 쿠키 + CSRF | 현재 세션 폐기                                      |
| `GET`    | `/api/files`        | 세션 쿠키        | `files`와 `total_bytes` 조회                        |
| `PUT`    | `/api/files/{name}` | 세션 쿠키 + CSRF | 요청 본문의 파일 바이트를 저장하고 `201` 응답       |
| `GET`    | `/api/files/{name}` | 세션 쿠키        | 파일 다운로드                                       |
| `DELETE` | `/api/files/{name}` | 세션 쿠키 + CSRF | 파일 영구 삭제                                      |

파일명은 URL 인코딩해야 합니다. CSRF가 필요한 요청은 `/api/session`에서 얻은 토큰을
`X-CSRF-Token` 헤더에 담습니다. 업로드는 multipart 형식 대신 파일 바이트 자체를 전송하며,
성공 응답의 `name`에서 중복 처리 후 실제 저장된 이름을 확인할 수 있습니다.
파일 목록의 각 항목에는 `name`, `size`(바이트), `modified`(Unix timestamp)가 포함됩니다.

## 프로젝트 구조

```text
app/
├── main.py              # 인증, 파일 API, 정적 자산 제공
└── static/
    ├── index.html       # 파일 관리 화면
    ├── login.html       # 로그인 화면
    ├── app.js           # 파일 목록, 업로드 큐, 다운로드·삭제
    ├── login.js         # 로그인 처리
    ├── theme.js         # 테마 전환과 저장
    ├── app.css          # 공통 스타일과 반응형 레이아웃
    └── mark.svg         # 서비스 아이콘
tests/test_app.py        # API와 파일 저장 동작 테스트
.github/workflows/ci.yml # Python·웹 검사
.env.example            # 환경 변수 예제
Dockerfile              # Python 3.14 기반 컨테이너
compose.yaml            # 서비스와 호스트 저장 폴더 설정
pyproject.toml           # Python 의존성과 Ruff 설정
uv.lock                  # Python 의존성 잠금 파일
package.json             # 개발 도구와 검사 스크립트
package-lock.json        # npm 의존성 잠금 파일
```
